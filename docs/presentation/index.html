Framework Selection & Trade-Off Analysis

Design Decision

Evaluating candidate architectures against operational SLAs, determinism, and token efficiency:

Architecture Pattern Core Mechanism SLA Predictability Loop Safety Decision Rationale
Unconstrained ReAct Dynamic LLM tool-calling loop Unpredictable (5s–30s) High infinite loop risk REJECTED: Enterprise SLAs cannot tolerate non-deterministic tool exploration.
Multi-Agent Swarm / Debate Multiple persona agents debating Poor (10x token overhead) Moderate drift risk REJECTED: Excessive latency (>15s) and token cost with no safety gain.
LlamaIndex Workflows Event-driven async steps Moderate Controlled REJECTED: Event-driven async paradigm adds needless complexity to a sequential state machine.
LangGraph StateGraph Typed acyclic/bounded-cyclic FSM Guaranteed (< 2.0s) Strictly Bounded (K ≤ 2) CHOSEN: Complete determinism, isolated node testing, typed state, and compile-time cycle bounds.

The Core Philosophy: Human Domain Architect & AI Force Multiplier

Active Steering

In modern agentic development, anyone can prompt an LLM to generate unstructured scripts. True engineering seniority lies in governing the agent: imposing strict architectural constraints, directing the methodology, validating mathematical behaviors, and rejecting superficial shortcuts.

Throughout this sprint, the human candidate acted as the Chief Architect and Director. The AI agent did not "invent" the system independently. The human instructed the agent step-by-step: mandating the authoring of an IEEE 830 SRS first, defining the SDD architectural blueprint, selecting the LangGraph state machine over ReAct patterns, formulating the formal data science metrics engine, and enforcing strict data governance. Every node boundary, threshold equation, and state transition was explicitly commanded, reviewed, and approved by the human before a single line was committed.

Root-Cause Failure Mode Analysis & Surgical Interventions

Engineering Narrative

Why V1 Failed at Action Routing

  • GapNode Field Mapping Bug: Over 50% of required template fields (e.g. is_there_a_safety_risk, affected_circuits_or_area) were unmapped, causing the node to perceive all fields as missing.
  • Confidence Over-Penalization: Missing non-critical fields plummeted composite confidence below 0.40, causing 100% of cases to dump into ROUTE_TO_HUMAN.
  • Sub-clause Safety Masking: Courteous introductory sentiment (e.g. "No rush at all...") diluted physical hazard signals in the LLM.
  • Evaluation Metric Flaw: Evaluator script inspected the post-clarification empty gap set instead of pre-clarification intake.

The Deliberate V2 Architectural Interventions

  • Discrete Threshold Banding: Missing fields now strictly bound confidence to [0.45, 0.70], cleanly triggering NEEDS_CLARIFICATION.
  • Hazard Dominance Directive: Physical danger signals unconditionally force P1 urgency, forbidding polite phrasing from discounting safety.
  • Implicit Context Inference: LLM prompt instructed to recognize informal proxies (e.g. building name acts as room location).
  • Full GapNode Coverage: Mapped all 8 catalogue schemas and converted safety booleans into truthy evaluation strings.

Mathematical Formulations & Calibration Curves

          Data Science Proofs
        


        

          

            
1. Why Macro F1 is Mandatory over Weighted F1

            

              
Macro-Averaged F1 Equation

              F1macro = 1|C| ∑c ∈ C 2 × Pc × RcPc + Rc
            

            

              In operational dispatch, catastrophic emergencies (P1) and hazmat escalations (HUMAN) are rare relative to routine plumbing requests. Weighted F1 allows high-volume routine classes to artificially inflate the score even if the agent completely fails on safety escalations. Macro F1 weights all 3 operational classes equally (33.3%), ensuring true production reliability.
            

          


          

            
2. The Asymmetric Safety Cost Penalty

            

              
Asymmetric Loss Formulation

              Costsafety = (100 × FNP1) + (5 × FPP1) + (1 × Estd)
            

            

              A missed electrical fire (FNP1) causes property loss or death (Cost ≈ $100,000+); an unnecessary emergency truck roll (FPP1) costs a nominal callout fee (Cost ≈ $150). The 100:5 penalty ratio reflects enterprise economics. FS-ID achieved Costsafety = 0.
            

          

        


        

          
3. Calibration Dynamics: Brier Score & ECE vs. Operational Correctness

          

            
Brier Score & Expected Calibration Error (ECE)

            BS = 1N ∑i=1N (pi − yi)2 = 0.177   •   ECE = ∑m=1M |Bm|N |acc(Bm) − conf(Bm)| = 0.291
          

          

            The Calibration Trade-Off: Notice that Brier Score (0.177) and ECE (0.291) slightly degraded from V1. Why? V1 was universally low-confidence, clustering homogeneously around 0.25. In V2, the system enforces discrete threshold banding ([0.45, 0.70] for clarification) rather than continuous probability estimation. In dispatch operations, discrete decision correctness (0.908 F1) is far more important than continuous probability smoothness.

Core Prompt Engineering Directives

The Two Biggest Production Risks

          Critical Assessment
        


        

          

            
Risk 1: Provider Rate Limits & Outages During Storm Surges

            

              The Threat: During severe weather events, facility incident volume surges 50x. External LLM APIs (Gemini, Claude, OpenAI) can experience latency spikes or HTTP 429 rate limit throttling.


              Our Mitigation: The BaseLLMClient adapter supports seamless multi-provider fallback (Gemini → Claude → OpenAI) with exponential backoff and local FIFO request queueing.
            

          


          

            
Risk 2: Cross-Trade Cascade Hazards Exceeding Single Trades

            

              The Threat: A major water pipe bursts directly above a high-voltage electrical distribution panel. Dispatching solely a plumber or solely an electrician creates physical danger and delays.


              Our Mitigation: The GapNode detects cross-trade physical collisions and unconditionally forces ROUTE_TO_HUMAN with a synthesized multi-trade coordination brief.

        Ecosystem Analysis
        
Model Context Protocol (MCP) Critique

        

          A nuanced technical assessment: does Anthropic's Model Context Protocol provide meaningful value 
          for field services dispatch, and where should it be applied?
        

      


      

        

          
The Case FOR vs. AGAINST MCP in FS-ID

          Architectural Evaluation
        


        

          

            
The Case FOR MCP

            
    
              
  • Enterprise ERP Interoperability: Exposing standardized tool schemas for ServiceNow, SAP PM, and IBM Maximo across heterogeneous field tools.
    • 
              
  • Cross-Agent Collaboration: Allowing the dispatch agent to seamlessly query a facility IoT sensor agent or an inventory warehouse agent via standard JSON-RPC.
    • 
              
  • Vendor-Agnostic Extensibility: Third-party contractors can publish their availability schemas as standard MCP resources.
    • 
            

          


          

            
The Case AGAINST MCP in Core Triage

            
    
              
  • Transport Latency Overhead: JSON-RPC over stdio/HTTP introduces serialization delays conflicting with sub-second triage SLAs.
    • 
              
  • In-Memory Catalogue Efficiency: The 8-template service catalogue is static and indexed in memory (O(1) lookup). Wrapping it in an MCP server introduces unnecessary network failure points.
    • 
              
  • Loss of Deterministic Bounds: Letting the LLM dynamically call external MCP tools violates our strict LangGraph finite state machine constraints.
    • 
            

          

        


        

          Architectural Recommendation: Retain the deterministic LangGraph state machine for all internal cognitive triage logic. Utilize MCP strictly as an external boundary adapter when publishing dispatches to external enterprise ERPs or querying live facility telemetry.
